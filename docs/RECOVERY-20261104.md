## Candidate behavior

scripts/sammler.py delegates to fomo_agent.collector. Regular operation and recovery
use the SAME command, lock identity (resolved DB path), steps and due-state.
A kernel file lock excludes concurrent supervisors; a worker lock also excludes
recovery while an orphan child survives a supervisor crash. Each child has a
120-second self-expiry (30s for local closing health). The supervisor bounds its
own timed-out child cleanup to 30s. A tick reserves 60s for closing health and its
cleanup, subtracts collection cleanup before each launch, and self-expires with
exit 124 at its 61..600s tick deadline, including SQLite/metadata stalls. Startup,
DB connection and zero-credit bootstrap precede that tick deadline; the scheduler
outer deadline must cover those too. An unresponsive/unavailable DB can prevent
persisting diagnostics; this is an explicit failure, never a green result.

Success is finished_at with no error and no errors/stopped/skipped/budget flags; attempt is
started_at independently. Failures persist in sammler_recovery. Transient retry
spacing: 60, 120, 240 seconds; subsequent attempts at most every six hours.
Auth/permanent failures require operator intervention, budget failures wait until
next UTC calendar month. No automatic key rotation or refresh. Nonzero step errors,
health failures and deferred error cooldowns propagate as collector exit 1.

The same tick repairs only stale/due steps then ALWAYS attempts fresh local health,
including --only runs, collection cooldown, budget/auth/error and collection-deadline
paths. Bootstrap failure runs only closing health and returns 1. Health ignores
historical sammler_recovery cooldown and its own success cadence; diagnostic BADs
do not accumulate collection backoff. Its subprocess has at most 30s to evaluate.
No network fallback is allowed in closing health: no-fill active rosters report
router BAD/unknown rather than claim health without chain evidence. Existing CLI
health retains its original optional chain probe. Historical gap BADs and all
thresholds remain unchanged. First or partial holdings RPC stops return exit 1,
persist transient backoff and retain already committed balances and run statistics.
Historical stopped runs do not count toward successful cadence.

FomoApi reserves every HTTP attempt in a separate committed BEGIN IMMEDIATE SQLite
transaction before sending. Hard ceiling min(configured cap,1000); zero does not
disable it. Failed, timed-out or crashed requests are never refunded. Bootstrap
uses legacy paid runs once; uncertain historical failures conservatively consume
all headroom. The explicitly recognizable missing-key-before-HTTP exception is
known zero, not unknown network consumption. Calendar accounting is UTC.

The ceiling applies to callers running this patched source. Old source versions or
external clients using the same API account cannot be constrained by this local
ledger. Integration must update all paid callers together, not just schedule a
candidate next to the old collector.
